# Windows 验证方法与证据边界

在 Windows PowerShell 运行 `scripts/Build-Windows.ps1`，以进程退出码为准。
完整测试分别覆盖 engine 全部包及 desktop 的 desktop,production 标签。
测试本地监听使用临时端口；不要运行第二套正式客户端占用现用 1080/1081/1082。

重点回归：

- 默认空目标/严格 TLS；单 IPv4 校验、设置往返、无个人配置目录复用；
  参数不含 OAuth code，不开启 TUN/upstream。
- 限定端点的 TLS 本地模拟测试：过期、自签名、错误身份的证书，
  只有显式开关且确切端点能成功；其他 IP、端口、域名及认证 HTTPS 拒绝。
  节点 TLS 延迟探测使用同一策略；发行 CLI 在请求网络前拒绝旧 EasyConnect。
- 可直连的本地对照目标，在强制 VPN 但无可用隧道时，SOCKS 仍失败；
  不把监听或进程本身当作隧道成功证据。
- 健康快照拒绝 PID/创建时间/runID、时间、目标或 TLS 模式不匹配，
  并覆盖引擎退出、生命周期及日志显示。
- WebView2 CDP Fetch 的处理器与回调解析单元测试。
  真实 WebView2 302/脚本跳转的零回调请求回归来自原本机版的受控模拟；
  本公开源码未重新启动真实认证窗口，不能据此声称全部 GUI 行为已重新验收。

构建脚本同时校验模块缓存、生成依赖许可、编译、检查引擎版本、解包检查 ZIP 内容和摘要。
远程 CI 需要将源码自行放入仓库后才会运行，本次准备没有上传或触发 GitHub 工作流。

后续人工验收应在停用其他端口占用后进行：保存自己的目标，登录，验证托盘悬停与菜单、
关闭隐藏、重复启动、断开、退出和故障重连，再隔离官方 VPN 对照 SOCKS 负向结果。
只有确认实际走第三方隧道后，才配置自己的 Clash 单目标规则、测 SSH 握手/登录和原有代理流量。
不要将原本机环境的通过记录当成公开版在另一台电脑上的通过结果。
